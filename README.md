# Skills_Claude

Инструкции агентов конвейера «Штаб» — общие для любых проектов: о конкретном проекте агент узнаёт из его `CLAUDE.md`, раздел «Для конвейера».

- `agents/executor.md` — исполнитель: берёт issue с меткой `готово` и доводит его до PR с отчётом; сливает только человек.

- `agents/reviewer.md` — ревьюер: читает PR бота после зелёных проверок и отдаёт вердикт «можно сливать» / «не сливать»; в GitHub сам не пишет.
- `agents/resolver.md` — развязчик: после слияния вливает основную ветку в PR бота с конфликтом и пушит; не уверен — комментарий владельцу.
- `agents/specifier.md` — спецификатор: правила записи задачи из сырой просьбы — признаки «готово», контекст для исполнителя, вопросы, класс и оценка. Читают сессия, которая продумывает задачи, аналитик и будущий запуск спецификатора.

- `.github/workflows/executor.yml` — общий workflow исполнителя: проект вызывает его своим коротким файлом по метке `готово`, со своим секретом `CLAUDE_CODE_OAUTH_TOKEN` (токен подписки, `claude setup-token`).
- `.github/workflows/reviewer.yml` — ревьюер: проект зовёт его из того же файла, когда закончились «Проверки PR» (`workflow_run`). Комментарий вердикта и метку `можно-сливать` / `не-сливать` ставит `scripts/review.sh`.
- `.github/workflows/resolver.yml` — развязчик: проект зовёт его из того же файла, когда слит PR; исполнитель — сам, после своей очереди (PR, открытый после слияния).
- `scripts/` — шаги без Claude: очередь, ворота и вердикт ревьюера, поиск конфликтов, замер прогона. `DRY_RUN=1` — только показать решение.
- `scripts/connect-project.sh` — подключение проекта к конвейеру одной командой: метки, шаблон «Задача», файл «Агенты», «Проверки PR» по шаблону Node, раздел «Для конвейера» — PR-ом; `--protect` — защита основной ветки. Шаблоны — `templates/project/`. Человеку остаются доступ App и секрет.

Правки — только с согласия владельца: они сразу меняют агентов во всех проектах.
